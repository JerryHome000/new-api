这一页说明两件事：模型是怎么计费的，以及为什么会有「分组倍率」。

## 计费方式

### Token 是什么

Token 是模型处理文本的基本单位。粗略估算：

- 1 个英文单词约 1–2 个 Token；
- 1 个汉字约 1.5–2 个 Token。

### 费用怎么算

```text
费用 = (输入 Token × 输入单价 + 输出 Token × 输出单价) × 分组倍率
```

举个例子（单价仅为示意）：

- 输入 500 Token，输出 300 Token；
- 模型输入单价 ¥2 / 百万 Token，输出单价 ¥10 / 百万 Token；
- 分组倍率 0.5x。

```text
(500 × 2 + 300 × 10) ÷ 1,000,000 × 0.5 = ¥0.002
```

按次计费的模型（例如部分图片、视频模型）以每次调用或每秒时长计价，同样会乘以分组倍率。

## 省钱技巧

### 按任务选模型

- 简单任务（改写、翻译、小修改）用轻量模型；
- 复杂规划交给能力更强的模型，例如 `{{CLAUDE_MODEL}}`；
- 大量代码实现可以用 `{{GPT_MODEL}}` 这类性价比高的模型。

### 减少不必要的消耗

- **控制输出长度**：让工具只输出需要的内容。
- **提示词写具体**：减少来回追问。
- **复用上下文**：在同一会话里继续工作更容易命中缓存，缓存部分的输入价格通常远低于原价。

### 关注用量

控制台的 [数据看板](/dashboard) 和 [使用日志](/usage-logs) 可以看到余额、每日消费、各模型和各分组的用量。

## 常见问题

**怎么选分组最合适？**

> **待补充** · 本站的分组推荐。

**为什么同一个模型在不同分组价格不同？**

不同分组背后的资源和线路不同，倍率也不同。倍率越低越便宜，但稳定性、缓存命中率和可用工具可能有差别，请按 [分组说明](#分组说明) 选择。
